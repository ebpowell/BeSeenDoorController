Since your router manages the dynamic IP updates, the setup isolates cleanly to your Docker host. Setting up an Nginx reverse proxy container in front of your API container requires three main steps: structuring the certificate bundle, configuring the Nginx virtual host, and orchestrating the bridge network in Docker Compose.

---

### 1. Bundle the Certificates on the Host

Ensure your host project directory has the combined certificate chain and private key accessible for volume mounting.

1. Create a `certs` folder in your project root:
```bash
mkdir -p ./certs

```


2. Combine the primary server certificate provided by No-IP with the intermediate CA bundle (order matters: leaf cert first, then intermediate):
```bash
cat yourhost_ddns_net.crt ca_bundle.crt > ./certs/fullchain.pem

```


3. Move your private key and restrict its permissions:
```bash
mv yourhost.key ./certs/privkey.pem
chmod 600 ./certs/privkey.pem

```



---

### 2. Configure Nginx (`nginx.conf`)

Create an `nginx.conf` file in your project directory. This configures HTTP-to-HTTPS redirection, enforces modern TLS 1.2/1.3 parameters, and routes inbound traffic over Docker's internal network to your API service container.

```nginx
events {
    worker_connections 1024;
}

http {
    # Hide Nginx version tokens for security
    server_tokens off;

    # 1. Port 80: Enforce HTTPS Redirect
    server {
        listen 80;
        server_name yourhost.ddns.net;

        location / {
            return 301 https://$host$request_uri;
        }
    }

    # 2. Port 443: Terminate TLS & Proxy to API Container
    server {
        listen 443 ssl;
        http2 on;
        server_name yourhost.ddns.net;

        # Certificate paths mapped inside the container
        ssl_certificate /etc/nginx/certs/fullchain.pem;
        ssl_certificate_key /etc/nginx/certs/privkey.pem;

        # TLS Hardening
        ssl_protocols TLSv1.2 TLSv1.3;
        ssl_ciphers HIGH:!aNULL:!MD5:!3DES;
        ssl_prefer_server_ciphers off;
        ssl_session_cache shared:SSL:10m;
        ssl_session_timeout 1d;
        ssl_session_tickets off;

        # Proxy to API service by container service name
        location / {
            proxy_pass http://api_backend:8000;
            
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto https;
            
            # WebSocket & persistent connection support
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection "upgrade";
        }
    }
}

```

---

### 3. Orchestrate with Docker Compose (`docker-compose.yml`)

Wire both containers together on an internal bridge network. Notice that **only the Nginx container exposes public ports (80/443)** to the host. The API container remains inaccessible from the outside except through the proxy.

```yaml
services:
  nginx-proxy:
    image: nginx:alpine
    container_name: nginx-ssl-proxy
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
      - ./certs:/etc/nginx/certs:ro
    depends_on:
      - api_backend
    networks:
      - internal_net

  api_backend:
    image: your-api-image:latest # or build: .
    container_name: api_backend
    restart: unless-stopped
    expose:
      - "8000" # Exposed internally to the Docker network, not the host
    environment:
      - PORT=8000
    networks:
      - internal_net

networks:
  internal_net:
    driver: bridge

```

---

### 4. Verification Steps

1. **Start the stack:**
```bash
docker compose up -d

```


2. **Verify Nginx read the certificate without errors:**
```bash
docker compose logs nginx-proxy

```


*Expected output:* Clean startup logs without `BIO_new_file` or SSL key mismatch errors.
3. **Test the TLS handshake and chain resolution:**
```bash
curl -Iv https://yourhost.ddns.net

```


*Verification:* Ensure the output confirms HTTP/2 (or HTTP/1.1) 200 OK, shows the SSL handshake completed successfully, and lists the verified certificate issuer without warnings.
